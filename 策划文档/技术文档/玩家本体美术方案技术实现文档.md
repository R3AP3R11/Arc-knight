# 玩家本体美术方案技术实现文档

## 1. 文档目的

本文档定义玩家本体的 Canvas 矢量绘制、动画、射击和护盾表现方案。

玩家本体由三部分组成：

```text
玩家本体
├── 主体
│   ├── 正六边形
│   ├── 内层武器颜色圆环
│   ├── 外层武器颜色圆环
│   └── 白色防护圆环
├── 武器
│   ├── 武器圆环
│   └── 绕环旋转的白色小球
└── 护盾
    └── 跟随鼠标方向的 1/3 圆环
```

全部元素使用 Phaser `Graphics` 进行 Canvas 矢量绘制，不使用图片、Sprite 或外部纹理。

## 2. 当前实现基础

当前玩家在 `src/game-scene.js` 中使用简单圆形绘制：

```js
g.fillStyle(0x51b9ff);
g.fillCircle(this.player.x, this.player.y, 13);
```

当前游戏循环已经具备：

- 玩家位置更新。
- 键盘移动。
- 鼠标按键检测。
- 子弹创建和移动。
- 墙体碰撞。
- 敌人命中处理。
- 每帧调用 `draw()` 重绘场景。

本方案将玩家绘制、武器动画、射击状态和护盾状态整合到现有 `update()` / `draw()` 流程中。

## 3. 坐标与尺寸约定

### 3.1 坐标

玩家中心点记为：

```js
const center = {
  x: this.player.x,
  y: this.player.y
};
```

角度约定：

- `0` 弧度：鼠标指针右侧方向。
- 正角度：顺时针或逆时针方向取决于 Canvas 坐标计算方式，统一通过 `Math.cos()` / `Math.sin()` 计算。
- 所有圆环均以玩家中心点为圆心。

### 3.2 尺寸

需求中的“大小 30px”统一解释为正六边形外接圆直径 30px，即外接半径 15px。

| 元素 | 尺寸 |
|---|---:|
| 正六边形外接直径 | 30px |
| 正六边形外接半径 | 15px |
| 主体内层圆环厚度 | 3px |
| 主体外层圆环厚度 | 6px |
| 内外主体圆环间距 | 6px |
| 正六边形与第一层圆环间距 | 12px |
| 主体白色圆环厚度 | 8px |
| 主体最外圆环与武器圆环间距 | 3px |
| 武器圆环厚度 | 8px |
| 武器白色小球直径 | 8px |
| 护盾圆环厚度 | 12px |
| 护盾与武器圆环间距 | 3px |

“间隔 20px”用于主体白色圆环与武器环之间的结构间隔，具体半径由各层外半径累加计算，不直接使用固定中心距离覆盖前面层级。

## 4. 数据结构设计

### 4.1 武器配置

建议在运行时增加玩家武器配置：

```js
const DEFAULT_WEAPON = {
  id: 'default',
  ringColor: '#ff9f43',
  trailColor: '#ff9f43',
  bulletColor: '#ffd166',
  bulletSpeed: 500,
  fireInterval: 180
};
```

字段定义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 武器类型 ID |
| `ringColor` | string | 主体武器相关圆环及武器环颜色 |
| `trailColor` | string | 子弹拖尾颜色 |
| `bulletColor` | string | 子弹主体颜色 |
| `bulletSpeed` | number | 子弹速度 |
| `fireInterval` | number | 连续射击间隔，单位毫秒 |

默认武器颜色为橙色：

```text
ringColor  = #ff9f43
trailColor = #ff9f43
```

### 4.2 玩家运行时状态

将现有玩家运行时对象扩展为：

```js
this.player = {
  ...l.spawn,
  r: 15,
  weapon: DEFAULT_WEAPON,
  weaponAngle: 0,
  weaponAngularVelocity: Phaser.Math.DegToRad(180),
  previousFireDown: false,
  firing: false,
  shieldActive: false,
  shieldAngle: 0
};
```

状态字段：

| 字段 | 说明 |
|---|---|
| `weaponAngle` | 武器白色小球当前角度 |
| `weaponAngularVelocity` | 小球当前角速度 |
| `previousFireDown` | 上一帧鼠标左键状态 |
| `firing` | 是否处于长按射击状态 |
| `shieldActive` | 是否激活护盾 |
| `shieldAngle` | 护盾中心方向角 |
| `weapon` | 当前武器配置 |

## 5. 主体矢量绘制

### 5.1 绘制顺序

绘制顺序从内到外：

```text
1. 正六边形，其中三个顶角点连接至中心点，形成一个黑色"Y"型
2. 第一层武器颜色圆环，厚 3px
3. 第二层武器颜色圆环，厚 6px
4. 白色主体圆环，厚 8px
5. 武器圆环，厚 8px
6. 武器白色小球
7. 护盾圆环
```

护盾建议最后绘制，确保激活时视觉上位于玩家外围，并能清晰显示防御方向。

### 5.2 正六边形与黑色 Y 型结构

正六边形角朝上，外接半径为 15px。正六边形本体作为最内层主体，内部增加黑色 Y 型结构：从中心点连接至正六边形的三个顶角点。

三个连接顶角应选择呈 120° 等间隔分布的顶点，形成稳定的三向 Y 型结构：

- 顶部顶角。
- 左下顶角。
- 右下顶角。

黑色 Y 型结构只绘制三条从中心点到顶角的线段，不连接其他顶角，也不填充额外三角形区域。

建议参数：

| 参数 | 值 |
|---|---:|
| 正六边形外接半径 | 15px |
| 六边形起始角 | `-Math.PI / 2` |
| Y 型连接线数量 | 3 |
| Y 型连接线宽度 | 3px |
| Y 型颜色 | `#000000` |
| Y 型连接端点 | 六边形顶部、左下、右下顶角 |

顶点计算：

```js
function getHexagonPoints(x, y, radius) {
  return Array.from({ length: 6 }, (_, index) => {
    const angle = -Math.PI / 2 + index * Math.PI / 3;
    return {
      x: x + Math.cos(angle) * radius,
      y: y + Math.sin(angle) * radius
    };
  });
}
```

绘制正六边形本体和黑色 Y 型结构：

```js
function drawHexagon(g, x, y, radius, fillColor) {
  const points = getHexagonPoints(x, y, radius);

  g.fillStyle(color(fillColor));
  g.beginPath();
  g.moveTo(points[0].x, points[0].y);
  points.slice(1).forEach(point => g.lineTo(point.x, point.y));
  g.closePath();
  g.fillPath();

  g.lineStyle(3, 0x000000, 1);
  g.beginPath();
  g.moveTo(x, y);
  g.lineTo(points[0].x, points[0].y);
  g.moveTo(x, y);
  g.lineTo(points[3].x, points[3].y);
  g.moveTo(x, y);
  g.lineTo(points[4].x, points[4].y);
  g.strokePath();
}
```

在当前顶点顺序下：

- `points[0]` 为顶部顶角。
- `points[3]` 为底部顶角。
- `points[4]` 为左下顶角。

如果项目坐标系或顶点顺序调整，应通过顶点方向确认连接的是顶部、左下和右下三个顶角，不能只依赖数组下标。

Y 型线段端点应落在六边形顶角，中心点为玩家中心。线宽固定为 3px，颜色固定为黑色，不随武器颜色变化。正六边形的填充颜色仍可使用主体固定色或武器主色的深色版本，但不应覆盖黑色 Y 型线段。

### 5.3 圆环绘制

Phaser `Graphics` 使用 `strokeCircle` 绘制圆环：

```js
function drawRing(g, x, y, radius, thickness, ringColor) {
  g.lineStyle(thickness, color(ringColor), 1);
  g.strokeCircle(x, y, radius);
}
```

为避免不同 Phaser 版本对 `lineStyle` 的兼容差异，圆环统一使用描边，不使用两个填充圆相减。

### 5.4 主体半径计算

设：

```text
R_hex = 15
G_hex_ring = 12
T_ring_1 = 3
G_ring = 6
T_ring_2 = 6
T_body_white = 8
```

第一层圆环中心半径：

```text
R_ring_1 = R_hex + G_hex_ring + T_ring_1 / 2
          = 15 + 12 + 1.5
          = 28.5px
```

第二层圆环中心半径：

```text
R_ring_2 = R_ring_1 + T_ring_1 / 2 + G_ring + T_ring_2 / 2
          = 28.5 + 1.5 + 6 + 3
          = 39px
```

白色主体圆环中心半径：

```text
R_body_white = R_ring_2 + T_ring_2 / 2 + 20 + T_body_white / 2
             = 39 + 3 + 20 + 4
             = 66px
```

实际实现中建议将半径定义为集中配置，便于根据视觉效果微调：

```js
const PLAYER_GEOMETRY = {
  hexRadius: 15,
  hexToRingGap: 12,
  innerRingThickness: 3,
  ringGap: 6,
  outerRingThickness: 6,
  bodyWhiteThickness: 8,
  bodyToWeaponGap: 3,
  weaponThickness: 8,
  shieldGap: 3,
  shieldThickness: 12
};
```

## 6. 武器圆环与旋转小球

### 6.1 武器圆环

武器圆环围绕主体白色圆环，厚度 8px，颜色读取当前武器配置：

```js
drawRing(
  g,
  player.x,
  player.y,
  weaponRingRadius,
  PLAYER_GEOMETRY.weaponThickness,
  player.weapon.ringColor
);
```

武器圆环与主体最外层保持 3px 间距：

```text
R_weapon = R_body_white
         + bodyWhiteThickness / 2
         + bodyToWeaponGap
         + weaponThickness / 2
```

### 6.2 武器小球位置

小球直径等于武器圆环厚度，即 8px，半径为 4px。

小球沿武器圆环中心线旋转：

```js
const orbitRadius = weaponRingRadius;
const orbX = player.x + Math.cos(player.weaponAngle) * orbitRadius;
const orbY = player.y + Math.sin(player.weaponAngle) * orbitRadius;
```

绘制：

```js
g.fillStyle(0xffffff);
g.fillCircle(orbX, orbY, PLAYER_GEOMETRY.weaponThickness / 2);
```

### 6.3 旋转速度

默认状态：

```text
角速度 = 180°/秒
```

转换为弧度：

```js
const NORMAL_WEAPON_SPEED = Phaser.Math.DegToRad(180);
```

长按左键射击：

```text
角速度 = 20°/秒
```

```js
const FIRING_WEAPON_SPEED = Phaser.Math.DegToRad(20);
```

每帧更新：

```js
player.weaponAngle += player.weaponAngularVelocity * dt / 1000;
```

角度超过一周后归一化：

```js
player.weaponAngle = Phaser.Math.Angle.Wrap(player.weaponAngle);
```

### 6.4 松开鼠标后的反向旋转

状态规则：

| 状态 | 小球旋转方向 | 角速度 |
|---|---|---:|
| 初始空闲 | 顺时针 | 180°/秒 |
| 左键长按射击 | 保持当前方向 | 20°/秒 |
| 松开左键完成一次射击 | 反向旋转 | 20°/秒或平滑恢复至 180°/秒 |
| 下一次空闲状态 | 使用松开后的方向 | 180°/秒 |

建议使用方向变量避免直接使用负速度：

```js
player.weaponDirection = 1;
player.weaponAngularVelocity = NORMAL_WEAPON_SPEED;
```

松开左键时：

```js
if (player.previousFireDown && !fireDown) {
  player.weaponDirection *= -1;
}
```

更新角度：

```js
const speed = fireDown
  ? FIRING_WEAPON_SPEED
  : NORMAL_WEAPON_SPEED;

player.weaponAngle += player.weaponDirection * speed * dt / 1000;
```

该实现保留“长按时减速、松开后反向”的表现，并避免每次松开都创建额外动画对象。

## 7. 射击实现

### 7.1 射击起点

子弹必须从武器小球位置发射，而不是从玩家中心点发射。

```js
const muzzle = getWeaponOrbPosition(player);
const angle = Phaser.Math.Angle.Between(
  muzzle.x,
  muzzle.y,
  pointer.x,
  pointer.y
);
```

子弹初始位置：

```js
const bullet = {
  x: muzzle.x,
  y: muzzle.y,
  vx: Math.cos(angle) * player.weapon.bulletSpeed,
  vy: Math.sin(angle) * player.weapon.bulletSpeed,
  angle,
  trailColor: player.weapon.trailColor,
  life: 0,
  trail: []
};
```

### 7.2 长按左键

鼠标左键状态通过：

```js
const fireDown = pointer.leftButtonDown();
```

或沿用项目已有的 `pointer.isDown`，但应明确区分左键和右键，避免护盾与射击共用一个状态。

长按期间：

- 持续按射击间隔生成子弹。
- 武器小球角速度降低到 20°/秒。
- 武器小球继续沿当前方向转动。
- 子弹起点实时跟随武器小球。

射击判断：

```js
if (fireDown && this.fireClock <= 0) {
  this.spawnBullet();
  this.fireClock = player.weapon.fireInterval;
}
```

### 7.3 射击结束

检测本帧与上一帧的左键状态：

```js
if (player.previousFireDown && !fireDown) {
  player.weaponDirection *= -1;
}

player.previousFireDown = fireDown;
```

该状态只在“按下 → 松开”的边沿触发一次，不会在持续按住时重复反向。

## 8. 子弹拖尾与行动轨迹

### 8.1 子弹结构

```js
{
  x,
  y,
  vx,
  vy,
  angle,
  trailColor,
  trail: [],
  life: 0
}
```

每帧记录当前位置：

```js
bullet.trail.unshift({ x: bullet.x, y: bullet.y });
bullet.trail.length = 6;
```

### 8.2 拖尾绘制

拖尾颜色读取武器配置：

```js
function drawBullet(g, bullet) {
  bullet.trail.forEach((point, index) => {
    const alpha = 1 - index / bullet.trail.length;
    const radius = Math.max(1, 3 - index * 0.4);

    g.fillStyle(colorWithAlpha(bullet.trailColor, alpha));
    g.fillCircle(point.x, point.y, radius);
  });

  g.fillStyle(color(bullet.trailColor));
  g.fillCircle(bullet.x, bullet.y, 4);
}
```

如果当前 Graphics API 不支持直接使用带透明度的颜色字符串，则使用 `g.fillStyle(hexColor, alpha)` 或将颜色解析为整数后传入 alpha。

### 8.3 不同武器的轨迹表现

第一版建议通过以下配置区分武器：

- `trailColor`：拖尾颜色。
- `bulletSpeed`：行动速度。
- `trailLength`：拖尾长度。
- `bulletRadius`：子弹大小。
- `trajectoryMode`：直线、散射或曲线轨迹。

本次默认使用直线轨迹：

```text
发射方向 = 武器小球位置 → 鼠标指针位置
```

后续武器若需要特殊轨迹，可在子弹更新阶段根据 `trajectoryMode` 扩展，不改变玩家绘制逻辑。

## 9. 护盾实现

### 9.1 显示条件

护盾默认隐藏。仅在右键持续按下时显示：

```js
const shieldDown = pointer.rightButtonDown();
player.shieldActive = shieldDown;
```

不建议使用 `pointer.isDown` 判断护盾，因为该字段可能同时覆盖左键和右键状态。

### 9.2 护盾方向

护盾方向跟随右键按住时鼠标指针相对于玩家中心的方向：

```js
player.shieldAngle = Phaser.Math.Angle.Between(
  player.x,
  player.y,
  pointer.x,
  pointer.y
);
```

鼠标离玩家中心过近时保留上一帧方向，避免方向角抖动：

```js
const distance = Phaser.Math.Distance.Between(
  player.x,
  player.y,
  pointer.x,
  pointer.y
);

if (distance > 2) {
  player.shieldAngle = Phaser.Math.Angle.Between(
    player.x,
    player.y,
    pointer.x,
    pointer.y
  );
}
```

### 9.3 1/3 圆环绘制

护盾为圆环的三分之一，建议定义为 120° 弧段：

```text
护盾弧度 = 2π / 3
护盾中心方向 = shieldAngle
起始角 = shieldAngle - π / 3
结束角 = shieldAngle + π / 3
```

绘制：

```js
function drawShield(g, player, radius, angle) {
  const arc = Math.PI * 2 / 3;
  const start = angle - arc / 2;
  const end = angle + arc / 2;

  g.lineStyle(12, 0x808080, 1);
  g.beginPath();
  g.arc(player.x, player.y, radius, start, end, false);
  g.strokePath();
}
```

护盾颜色固定为灰色：

```text
#808080
```

透明度可根据视觉效果设置为 0.85～1.0，但不改变防御判定。

### 9.4 护盾半径

护盾与武器圆环保持 3px 间距：

```text
R_shield = R_weapon
         + weaponThickness / 2
         + shieldGap
         + shieldThickness / 2
```

使用统一几何配置：

```js
const shieldRadius =
  weaponRingRadius
  + PLAYER_GEOMETRY.weaponThickness / 2
  + PLAYER_GEOMETRY.shieldGap
  + PLAYER_GEOMETRY.shieldThickness / 2;
```

## 10. 护盾防御判定

### 10.1 判定目标

护盾只防御朝向护盾弧段的敌方子弹或攻击，不改变玩家移动和射击规则。

当前项目子弹对象主要是玩家子弹，后续增加敌方子弹时应为敌方子弹增加：

```js
{
  owner: 'enemy'
}
```

护盾只处理 `owner === 'enemy'` 的攻击对象。

### 10.2 弧段命中判定

定义：

- `distance`：攻击物与玩家中心距离。
- `angleToAttack`：玩家指向攻击物的方向。
- `shieldAngle`：护盾中心方向。
- `shieldArc`：`2π / 3`。

攻击物同时满足以下条件时判定被护盾阻挡：

```text
distance 位于护盾半径附近
且
角度差 <= 护盾弧度 / 2
```

角度差需要使用环绕角度计算：

```js
function isShieldBlocking(player, object) {
  const distance = Phaser.Math.Distance.Between(
    player.x,
    player.y,
    object.x,
    object.y
  );

  const angle = Phaser.Math.Angle.Between(
    player.x,
    player.y,
    object.x,
    object.y
  );

  const diff = Phaser.Math.Angle.Wrap(angle - player.shieldAngle);
  const withinArc = Math.abs(diff) <= Math.PI / 3;
  const withinRadius = distance <= shieldRadius + object.radius;

  return player.shieldActive && withinArc && withinRadius;
}
```

为了让护盾阻挡发生在攻击命中玩家之前，更新顺序应为：

```text
更新敌方攻击物位置
  ↓
检测护盾阻挡
  ├─ 被阻挡：销毁攻击物，生成防御反馈
  └─ 未阻挡：继续检测玩家受击
```

### 10.3 当前版本兼容

当前代码未实现敌方子弹对象。第一阶段可以先完成：

- 护盾显示。
- 鼠标方向跟随。
- 护盾绘制。
- 防御判定函数预留。

当敌方弹道系统接入后，再调用 `isShieldBlocking()` 完成真实防御。

## 11. 游戏循环改造

建议将当前 `update()` 拆分为以下步骤：

```text
update(time, dt)
  ├─ 编辑模式：仅绘制编辑场景
  └─ 游戏模式
      ├─ updatePlayerMovement(dt)
      ├─ updateWeaponState(dt)
      ├─ updateShieldState()
      ├─ updateShooting(dt)
      ├─ updateBullets(dt)
      ├─ updateEnemies(dt)
      ├─ updateEnemyAttacks(dt)
      └─ draw()
```

核心状态更新：

```js
updateWeaponState(dt) {
  const pointer = this.input.activePointer;
  const fireDown = pointer.leftButtonDown();
  const shieldDown = pointer.rightButtonDown();

  if (this.player.previousFireDown && !fireDown) {
    this.player.weaponDirection *= -1;
  }

  this.player.firing = fireDown;
  this.player.shieldActive = shieldDown;

  if (shieldDown) {
    this.player.shieldAngle = Phaser.Math.Angle.Between(
      this.player.x,
      this.player.y,
      pointer.x,
      pointer.y
    );
  }

  const speed = fireDown
    ? Phaser.Math.DegToRad(20)
    : Phaser.Math.DegToRad(180);

  this.player.weaponAngle +=
    this.player.weaponDirection * speed * dt / 1000;
  this.player.weaponAngle = Phaser.Math.Angle.Wrap(this.player.weaponAngle);
  this.player.previousFireDown = fireDown;
}
```

## 12. 绘制函数拆分

不建议把全部绘制代码继续堆在 `draw()` 中。建议拆分为以下函数：

```js
function drawPlayer(g, player) {}
function drawPlayerBody(g, player, geometry) {}
function drawWeaponRing(g, player, geometry) {}
function drawWeaponOrb(g, player, geometry) {}
function drawShield(g, player, geometry) {}
function drawBullets(g, bullets) {}
function getWeaponOrbPosition(player, geometry) {}
```

主绘制流程：

```js
draw() {
  const l = ctx.state.level;
  const g = this.g;

  g.clear();
  drawBackground(g, l);
  drawWalls(g, l);
  drawEnemies(g, l);

  if (this.editing) {
    drawSpawn(g, l.spawn);
  } else {
    drawBullets(g, this.bullets);
    drawPlayer(g, this.player);
  }
}
```

玩家绘制函数：

```js
function drawPlayer(g, player) {
  drawPlayerBody(g, player, PLAYER_GEOMETRY);
  drawWeaponRing(g, player, PLAYER_GEOMETRY);
  drawWeaponOrb(g, player, PLAYER_GEOMETRY);

  if (player.shieldActive) {
    drawShield(g, player, PLAYER_GEOMETRY);
  }
}
```

## 13. 输入处理

### 13.1 鼠标按键

必须区分左键和右键：

| 按键 | 功能 |
|---|---|
| 鼠标左键长按 | 连续射击，武器小球减速 |
| 鼠标左键松开 | 完成当前射击，武器小球反向旋转 |
| 鼠标右键长按 | 显示并激活护盾 |
| 鼠标右键松开 | 隐藏并关闭护盾 |

推荐统一在 `update()` 中读取 Phaser Pointer 状态，不在 DOM 事件和 Phaser 事件之间重复维护状态。

### 13.2 浏览器右键菜单

如果右键护盾操作受到浏览器菜单影响，需要阻止 Canvas 上下文菜单：

```js
this.game.canvas.addEventListener('contextmenu', event => {
  event.preventDefault();
});
```

该逻辑只作用于游戏 Canvas，不影响编辑器其他页面区域。

## 14. 兼容与配置策略

### 14.1 不修改关卡文件的字段

玩家本体属于运行时表现，不建议第一版直接写入关卡 JSON。关卡文件只保存出生点：

```json
{
  "spawn": {
    "x": 130,
    "y": 300
  }
}
```

武器类型可先使用代码默认值，后续如果需要按关卡配置，再增加：

```json
{
  "player": {
    "weapon": "default"
  }
}
```

### 14.2 颜色格式

配置层统一使用十六进制字符串：

```text
#ff9f43
#ffffff
#808080
```

绘制层统一通过颜色转换函数转为 Phaser 数值：

```js
function color(value) {
  return Phaser.Display.Color.HexStringToColor(value).color;
}
```

## 15. 性能要求

全部图形每帧重绘，当前画布尺寸为 `900 × 600`，元素数量较少，Canvas Graphics 足以满足性能要求。

注意事项：

- 不在每帧创建 Phaser GameObject。
- 不为每颗子弹创建独立 Sprite。
- 子弹拖尾限制固定长度，例如 6～10 个点。
- 不在 `draw()` 中修改游戏状态。
- 射击、旋转和护盾状态在 `update()` 中更新。
- `draw()` 只读取状态并绘图。

## 16. 涉及文件

| 文件 | 改造内容 |
|---|---|
| `src/game-scene.js` | 玩家矢量绘制、武器旋转、射击起点、护盾显示和防御判定 |
| `src/state.js` | 可选：增加默认玩家武器配置或运行时常量 |
| `src/style.css` | 通常无需修改；仅在 Canvas 交互样式需要时调整 |
| `index.html` | 通常无需修改；如增加武器调试选择器，再增加 UI 控件 |
| 关卡 JSON | 第一版不增加玩家美术字段，仅保留 `spawn` |

建议第一版将几何常量和武器默认配置放在 `src/game-scene.js` 或独立的 `src/player-config.js` 中，避免把纯运行时表现写入关卡数据。

## 17. 分阶段实施

### 阶段一：主体矢量绘制

- 删除简单蓝色圆形玩家绘制。
- 增加正六边形。
- 增加两层武器颜色圆环。
- 增加白色主体圆环。
- 确认各层间距和尺寸。

完成标准：玩家本体静态结构符合设计稿，全部由 Canvas 矢量绘制。

### 阶段二：武器圆环与旋转小球

- 增加武器圆环。
- 增加白色旋转小球。
- 实现 180°/秒顺时针旋转。
- 实现长按左键时 20°/秒减速。
- 实现左键松开后反向旋转。

完成标准：小球沿武器圆环稳定旋转，速度和方向符合规则。

### 阶段三：射击与拖尾

- 子弹从小球位置生成。
- 左键长按连续射击。
- 子弹方向指向鼠标。
- 增加武器颜色对应的子弹拖尾。
- 保留现有墙体和敌人命中逻辑。

完成标准：射击视觉起点正确，子弹不会从玩家中心突然出现。

### 阶段四：护盾表现

- 右键长按显示灰色 1/3 圆环。
- 护盾方向跟随鼠标指针。
- 右键松开立即隐藏护盾。
- 增加护盾半径和绘制间距。

完成标准：护盾只在右键按住时显示，方向响应稳定。

### 阶段五：护盾防御

- 增加敌方攻击物的归属字段。
- 接入护盾弧段判定。
- 被护盾阻挡的攻击物销毁。
- 增加命中反馈和调试显示。

完成标准：护盾只防御其 1/3 圆环朝向区域内的攻击。

## 18. 验收标准

### 18.1 主体

1. 玩家主体由正六边形、两层彩色圆环和白色圆环组成。
2. 玩家最内层为正六边形，角朝上，外接直径为 30px，并包含从中心连接顶部、左下、右下三个顶角的黑色 Y 型结构。
3. Y 型结构由 3px 黑色线段组成，不连接其他顶角，不填充额外区域。
4. 第一层圆环厚 3px。
4. 第二层圆环厚 6px。
5. 两层圆环间距为 6px。
6. 正六边形与第一层圆环间距为 12px。
7. 白色主体圆环厚 8px。
8. 圆环颜色随武器类型变化。

### 18.2 武器

1. 武器圆环厚 8px。
2. 武器圆环与主体最外层间距为 3px。
3. 白色小球直径等于武器圆环厚度。
4. 空闲状态小球以 180°/秒旋转。
5. 左键长按时小球速度降低到 20°/秒。
6. 左键松开后小球反向旋转。
7. 子弹从白色小球位置发射。
8. 默认武器颜色为橙色。
9. 子弹拖尾颜色读取武器配置。

### 18.3 护盾

1. 护盾平时不显示。
2. 右键长按时显示。
3. 护盾为 1/3 圆环，弧度为 120°。
4. 护盾厚度为 12px。
5. 护盾与武器圆环间距为 3px。
6. 护盾颜色为灰色。
7. 护盾方向跟随右键按住时的鼠标方向。
8. 右键松开后护盾立即隐藏。
9. 护盾判定区域与视觉弧段一致。

### 18.4 回归

1. 玩家仍从关卡 `spawn` 位置开始。
2. 玩家移动不留下旧图形。
3. 编辑模式出生点显示正常。
4. 墙体碰撞不受玩家绘制改造影响。
5. 玩家子弹仍可命中墙体和敌人。
6. 关卡保存、加载和导出功能无回归。
7. Canvas 上右键不会弹出浏览器菜单。

## 19. 暂不实现范围

第一版暂不实现：

- 玩家主体旋转。
- 玩家受击闪烁和死亡动画。
- 武器切换 UI。
- 多种复杂子弹轨迹。
- 护盾耐久度。
- 护盾能量消耗和冷却。
- 护盾反弹攻击。
- 玩家本体粒子特效。
- 玩家形状自定义编辑器。

这些功能应在基础矢量结构、输入状态和碰撞判定稳定后再扩展。
