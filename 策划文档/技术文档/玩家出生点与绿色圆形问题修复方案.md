# 玩家出生点残留与绿色圆形问题修复方案

## 1. 问题概述

编辑器中存在两个问题：

1. 游戏开始后，玩家从蓝色出生点移动，出生点原位置仍保留蓝色圆形。
2. 编辑界面存在绿色圆形，但当前没有明确作用，也没有对应的游戏逻辑，需要删除。

## 2. 当前实现分析

### 2.1 蓝色出生点残留

`src/game-scene.js` 的 `draw()` 同时绘制了出生点和游戏中的玩家：

```js
g.fillStyle(0x45c8ff);
g.fillCircle(l.spawn.x, l.spawn.y, 14);
```

以及：

```js
if (!this.editing) {
  g.fillStyle(0x51b9ff);
  g.fillCircle(this.player.x, this.player.y, 13);
}
```

游戏模式下，出生点仍被绘制。玩家移动后，画布同时显示出生点和移动中的玩家，因此产生残留效果。

### 2.2 绿色圆形

绿色圆形由以下代码绘制：

```js
g.fillStyle(0x37d69a);
g.fillCircle(l.goal.x, l.goal.y, 14);
```

绿色圆形对应关卡数据中的 `goal` 字段。当前实现仅包含：

- 编辑器中绘制绿色圆形。
- 编辑器中通过 `goal` 工具设置位置。
- 游戏运行中没有目标点到达判定。
- 没有胜利流程或目标状态展示。

因此当前 `goal` 属于未完成的占位功能。根据需求，本次将其整体删除，而不只删除显示效果。

## 3. 修复目标

- 编辑模式显示蓝色玩家出生点。
- 游戏模式不再显示固定出生点，只显示当前移动中的玩家。
- 玩家移动时不留下旧位置图形。
- 删除绿色目标点的绘制、编辑工具、数据字段和默认配置。
- 不影响墙体、敌人、子弹、编辑器保存及关卡加载。

## 4. 具体改造方案

### 4.1 修复出生点绘制逻辑

修改 `src/game-scene.js` 的 `draw()`。

将出生点绘制限制在编辑模式：

```js
if (this.editing) {
  g.fillStyle(0x45c8ff);
  g.fillCircle(l.spawn.x, l.spawn.y, 14);
}
```

游戏模式下只绘制玩家当前位置：

```js
if (!this.editing) {
  g.fillStyle(0x51b9ff);
  g.fillCircle(this.player.x, this.player.y, 13);
}
```

`draw()` 已经在每次绘制开始时执行：

```js
g.clear();
```

因此只要不在游戏模式绘制 `l.spawn`，玩家移动后就不会出现出生点残留。

### 4.2 删除目标点绘制

删除 `src/game-scene.js` 中的绿色圆形绘制：

```js
g.fillStyle(0x37d69a);
g.fillCircle(l.goal.x, l.goal.y, 14);
```

### 4.3 删除目标点编辑逻辑

删除 `src/game-scene.js` 的目标点工具分支：

```js
else if (tool === 'goal') l.goal = { x, y };
```

删除后，点击目标点工具不会再修改关卡数据。目标点工具按钮也应同步从界面中移除，避免出现无效工具。

涉及文件：

- `index.html`：删除 `data-tool="goal"` 的工具按钮。
- `src/ui.js`：如果存在目标点专用 DOM 引用或显示逻辑，一并删除。
- `src/main.js`：如果存在目标点属性面板或事件绑定，一并删除。

### 4.4 删除默认目标点数据

修改 `src/state.js`：

```js
export const DEFAULT_LEVEL = {
  backgroundColor: '#0b1b2b',
  gridColor: '#173a55',
  showGridInPlay: false,
  walls: [...],
  enemies: [...],
  spawn: { x: 130, y: 300 }
};
```

删除：

```js
goal: { x: 820, y: 300 }
```

同时从 `normalizeLevel()` 删除：

```js
goal: data.goal || clone(DEFAULT_LEVEL.goal)
```

建议在归一化阶段清理旧数据中的 `goal` 字段，避免旧字段继续被保存：

```js
const normalized = {
  ...clone(DEFAULT_LEVEL),
  ...data,
  walls: normalizedWalls,
  enemies: normalizedEnemies,
  spawn: data.spawn || clone(DEFAULT_LEVEL.spawn)
};

delete normalized.goal;
return normalized;
```

具体实现时应结合当前 `normalizeLevel()` 结构，避免重复定义中间变量。

### 4.5 清理已有关卡数据

从以下关卡文件中删除 `goal` 字段：

- `data/levels/*.json`
- `data/drafts/*.json`

示例：

```json
{
  "spawn": {
    "x": 150,
    "y": 210
  }
}
```

不再包含：

```json
"goal": {
  "x": 820,
  "y": 300
}
```

即使暂时保留旧文件中的 `goal` 字段，只要 `normalizeLevel()` 不再使用该字段，运行时也不会绘制绿色圆形。但建议同步清理数据，避免无效字段长期保留。

## 5. 涉及文件

| 文件 | 修改内容 |
|---|---|
| `src/game-scene.js` | 游戏模式隐藏出生点；删除绿色圆形绘制；删除目标点设置逻辑 |
| `src/state.js` | 删除默认 `goal`；停止归一化 `goal` 字段 |
| `index.html` | 删除目标点工具按钮 |
| `src/ui.js` | 删除目标点相关 UI 引用，如存在 |
| `src/main.js` | 删除目标点相关事件绑定，如存在 |
| `data/levels/*.json` | 删除已有 `goal` 字段 |
| `data/drafts/*.json` | 删除已有 `goal` 字段 |

## 6. 兼容性处理

### 6.1 旧关卡兼容

旧关卡可能仍包含 `goal` 字段。加载时应忽略该字段，不将其用于绘制或编辑逻辑。

可选处理方式：

- 仅运行时忽略 `goal`，保留原 JSON 字段。
- 加载归一化时删除 `goal`，后续保存时自动清理。

推荐第二种方式，确保数据结构最终统一。

### 6.2 不影响出生点编辑

本次只调整出生点的显示范围，不删除 `spawn` 字段和 `spawn` 工具：

- 编辑模式仍显示蓝色出生点。
- 仍可通过出生点工具修改位置。
- 游戏开始时以 `l.spawn` 初始化 `this.player`。
- 游戏模式只显示 `this.player`。

## 7. 验证方案

### 7.1 出生点验证

1. 打开编辑模式，确认蓝色出生点正常显示。
2. 修改出生点位置，确认蓝色圆形随位置变化。
3. 进入游戏模式，确认只显示玩家当前位置。
4. 按移动键移动玩家，确认原出生位置没有蓝色圆形残留。
5. 多次停止、重新进入游戏，确认每次只创建一个玩家图形。
6. 游戏结束后重新开始，确认出生点不会作为额外图形留在画布上。

### 7.2 绿色圆形验证

1. 编辑界面不再显示绿色圆形。
2. 工具栏不再显示目标点工具。
3. 进入游戏模式不再显示绿色圆形。
4. 加载旧关卡后不再显示绿色圆形。
5. 保存关卡后 JSON 中不再产生 `goal` 字段。
6. 导出、导入关卡后不再恢复绿色圆形。

### 7.3 回归验证

1. 墙体仍可创建、移动、缩放、删除。
2. 敌人仍可创建、移动和删除。
3. 出生点仍可编辑。
4. 玩家仍从出生点开始游戏。
5. 玩家移动、射击和敌人逻辑正常。
6. 关卡草稿和正式关卡仍可保存。
7. 旧版关卡可以正常加载。

## 8. 实施顺序

### 第一步：修复出生点显示

- 修改 `src/game-scene.js`。
- 将出生点绘制限制到编辑模式。
- 保留游戏模式玩家绘制。

完成标准：玩家移动后出生点原位置不再显示蓝色圆形。

### 第二步：删除目标点逻辑

- 删除目标点绘制。
- 删除目标点工具按钮。
- 删除目标点设置事件。
- 删除默认 `goal` 配置。

完成标准：代码和界面中不存在可操作的目标点功能。

### 第三步：清理数据与兼容处理

- 删除关卡 JSON 中的 `goal` 字段。
- 在 `normalizeLevel()` 中忽略或删除旧 `goal` 字段。

完成标准：旧数据可加载，新保存数据不再包含无效目标点字段。

### 第四步：回归测试

- 验证出生点、玩家移动和关卡加载。
- 验证编辑器其他实体功能。
- 验证数据保存和导入导出。

## 9. 验收标准

1. 游戏开始后，出生点只用于初始化玩家，不作为游戏场景中的固定图形显示。
2. 玩家移动后，原出生位置不留下蓝色圆形。
3. 编辑模式仍显示出生点，方便策划调整位置。
4. 绿色圆形从编辑模式和游戏模式中完全消失。
5. 目标点工具从编辑器中移除。
6. 新关卡默认数据不包含 `goal` 字段。
7. 旧关卡包含 `goal` 字段时仍可正常加载。
8. 新保存的关卡数据不再写入 `goal` 字段。
9. 墙体、敌人、出生点和玩家移动功能无回归。
