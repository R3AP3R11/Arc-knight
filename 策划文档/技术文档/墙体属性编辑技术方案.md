# 墙体属性编辑技术方案

## 1. 文档目的

本文档定义关卡编辑器中墙体属性编辑能力的实现方案，使策划可以选中墙体后修改颜色、长度、厚度和位置，并通过画布手柄直接调整墙体尺寸。

目标能力：

- 选中墙体后显示属性面板。
- 修改墙体颜色、长度、厚度、X/Y 坐标。
- 在画布中拖拽墙体边角调整长度和厚度。
- 修改结果实时刷新并保存到草稿。
- 兼容已有不包含颜色字段的墙体数据。
- 墙体尺寸变化后同步影响碰撞和擦除判断。

## 2. 当前实现现状

当前墙体数据结构为：

```json
{
  "x": 200,
  "y": 160,
  "w": 30,
  "h": 90
}
```

当前已具备：

- 通过 `wall` 工具创建墙体。
- 墙体使用中心坐标 `x/y` 保存。
- 使用 `w/h` 保存墙体宽高。
- 选中工具支持移动墙体。
- 碰撞检测使用墙体宽高。
- 关卡数据整体保存到 JSON 草稿文件。

当前缺口：

- 墙体颜色在 `src/game-scene.js` 中硬编码为 `0x60758b`。
- 没有墙体属性面板。
- 无法通过数值输入修改墙体尺寸。
- 无法通过画布手柄调整墙体尺寸。
- 选中和擦除逻辑没有完全按照墙体实际范围命中。
- 旧数据没有颜色字段的兼容处理。

## 3. 目标架构

```text
墙体数据模型
  ├─ x/y：中心坐标
  ├─ w：长度
  ├─ h：厚度
  ├─ color：颜色
  └─ id：唯一标识
       │
       ├─ 属性面板
       │    └─ 修改字段 → 更新 state.level.walls
       │
       └─ 画布交互
            ├─ 拖动墙体 → 修改 x/y
            └─ 拖动尺寸手柄 → 修改 x/y/w/h
                         │
                         └─ 重绘场景 → 保存草稿
```

编辑器继续以 `state.level` 作为唯一数据源，属性面板和画布交互都直接修改当前选中的墙体对象，避免维护两套墙体状态。

## 4. 墙体数据结构

建议将墙体结构扩展为：

```json
{
  "id": "wall-1",
  "x": 200,
  "y": 160,
  "w": 120,
  "h": 24,
  "color": "#60758b"
}
```

### 4.1 字段定义

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 墙体唯一标识，便于选中、编辑和删除 |
| `x` | number | 墙体中心点 X 坐标 |
| `y` | number | 墙体中心点 Y 坐标 |
| `w` | number | 墙体长度，对应渲染矩形宽度 |
| `h` | number | 墙体厚度，对应渲染矩形高度 |
| `color` | string | 墙体颜色，建议使用 `#RRGGBB` 格式 |

长度和厚度沿用当前 `w/h` 字段，避免影响现有碰撞逻辑和关卡文件。

### 4.2 默认值与旧数据兼容

在 `src/state.js` 的 `normalizeLevel()` 中为旧墙体补充默认字段：

```js
const DEFAULT_WALL_COLOR = '#60758b';
const MIN_WALL_SIZE = 8;

walls: (data.walls || []).map((wall, index) => ({
  ...wall,
  id: wall.id || `wall-${index + 1}`,
  color: wall.color || DEFAULT_WALL_COLOR,
  w: Math.max(Number(wall.w) || 30, MIN_WALL_SIZE),
  h: Math.max(Number(wall.h) || 90, MIN_WALL_SIZE)
}))
```

默认值必须保证用户已有字段优先保留。旧关卡无需手工迁移，加载时自动补齐即可。

## 5. 墙体渲染

### 5.1 读取墙体颜色

修改 `src/game-scene.js` 中的墙体绘制逻辑，将硬编码颜色替换为墙体字段：

```js
g.fillStyle(parseColor(w.color || DEFAULT_WALL_COLOR));
g.fillRect(
  w.x - w.w / 2,
  w.y - w.h / 2,
  w.w,
  w.h
);
```

颜色转换统一封装：

```js
function parseColor(color) {
  return Number.parseInt(String(color).replace('#', ''), 16);
}
```

### 5.2 选中态与手柄

选中墙体后：

- 墙体增加高亮描边。
- 四个角绘制尺寸手柄。
- 手柄大小保持固定，不随墙体尺寸变化。
- 鼠标悬停手柄时显示调整尺寸光标。

手柄类型：

- `nw`：左上角。
- `ne`：右上角。
- `sw`：左下角。
- `se`：右下角。

## 6. 墙体属性面板

### 6.1 页面结构

在 `index.html` 的实体编辑区域新增墙体属性面板：

```html
<section id="wall-properties" hidden>
  <label>
    颜色
    <input id="wall-color" type="color">
  </label>

  <label>
    长度
    <input id="wall-width" type="number" min="8" step="1">
  </label>

  <label>
    厚度
    <input id="wall-height" type="number" min="8" step="1">
  </label>

  <label>
    X 坐标
    <input id="wall-x" type="number" step="1">
  </label>

  <label>
    Y 坐标
    <input id="wall-y" type="number" step="1">
  </label>
</section>
```

在 `src/ui.js` 中注册新增控件 ID。

### 6.2 面板显示规则

| 当前状态 | 面板行为 |
|---|---|
| 未选中实体 | 隐藏或禁用面板 |
| 选中墙体 | 显示墙体当前属性 |
| 选中其他实体 | 隐藏墙体属性面板 |
| 墙体被删除 | 清空并隐藏面板 |

### 6.3 属性修改流程

`src/main.js` 扩展现有 `sync()` 和事件绑定逻辑：

```text
用户修改输入框
  ↓
获取当前选中墙体
  ↓
校验并限制输入值
  ↓
更新 state.level.walls[index]
  ↓
重绘场景
  ↓
保存草稿
```

尺寸字段必须经过最小值限制：

```js
function updateWallSize(field, value) {
  const wall = getSelectedWall();
  if (!wall) return;

  const size = Number(value);
  if (!Number.isFinite(size)) return;

  wall[field] = Math.max(size, MIN_WALL_SIZE);
  redraw();
}
```

属性面板与墙体对象之间不保存独立副本，避免输入框数据与场景数据不一致。

## 7. 画布手柄调整尺寸

### 7.1 交互优先级

指针按下时按以下顺序判断：

```text
pointerDown
  ↓
命中当前选中墙体的尺寸手柄？
  ├─ 是：进入 resize 状态
  └─ 否：命中墙体主体？
       ├─ 是：进入 move 状态
       └─ 否：执行当前工具的其他逻辑
```

手柄命中必须优先于墙体主体命中，避免拖动手柄时被识别成移动墙体。

### 7.2 拖拽状态

建议增加：

```js
drag: {
  mode: 'move' | 'resize',
  handle: 'nw' | 'ne' | 'sw' | 'se' | null,
  wallIndex: 0
}
```

事件流程：

```text
pointerDown → 记录墙体索引和手柄类型
pointerMove → 修改墙体位置或尺寸并刷新画布
pointerUp   → 清理拖拽状态并保存草稿
```

拖拽过程中只刷新画布，`pointerUp` 时保存一次，避免频繁写入草稿文件。

### 7.3 固定对角点计算

尺寸调整采用“拖动一角、固定对角”的方式。

| 手柄 | 固定点 |
|---|---|
| `nw` | 右下角 |
| `ne` | 左下角 |
| `sw` | 右上角 |
| `se` | 左上角 |

以拖动右下角为例：

```js
const left = wall.x - wall.w / 2;
const top = wall.y - wall.h / 2;
const right = Math.max(pointer.x, left + MIN_WALL_SIZE);
const bottom = Math.max(pointer.y, top + MIN_WALL_SIZE);

wall.w = right - left;
wall.h = bottom - top;
wall.x = left + wall.w / 2;
wall.y = top + wall.h / 2;
```

拖动其他手柄时，根据手柄方向分别计算固定边和移动边，并保证 `w/h` 不小于最小值。

## 8. 选中、擦除与碰撞

### 8.1 统一墙体命中判断

当前固定中心距离判断无法准确覆盖尺寸变化后的墙体。建议统一使用 AABB 判断：

```js
function hitWall(wall, x, y) {
  return (
    x >= wall.x - wall.w / 2 &&
    x <= wall.x + wall.w / 2 &&
    y >= wall.y - wall.h / 2 &&
    y <= wall.y + wall.h / 2
  );
}
```

以下功能共用该判断：

- 选中墙体。
- 橡皮擦删除墙体。
- 画布手柄定位。
- 其他需要判断墙体覆盖范围的编辑操作。

### 8.2 碰撞检测

现有碰撞检测已经读取墙体 `w/h`，因此属性面板和画布手柄修改尺寸后，碰撞范围会自动同步。

需要回归验证：

- 子弹命中墙体边缘。
- 墙体变大后的新增区域可以阻挡子弹。
- 墙体变小后的原区域不再阻挡子弹。
- 修改墙体位置后碰撞位置同步变化。

## 9. 涉及文件

| 文件 | 改造内容 |
|---|---|
| `src/state.js` | 墙体默认颜色、唯一 ID、尺寸归一化、旧数据兼容 |
| `src/game-scene.js` | 读取墙体颜色、绘制选中态和尺寸手柄、处理拖拽调整尺寸、统一命中判断 |
| `src/main.js` | 属性面板同步、属性修改事件、选中状态联动、草稿保存 |
| `src/ui.js` | 注册墙体属性面板控件 |
| `index.html` | 增加墙体颜色、长度、厚度、位置输入控件 |
| `src/api.js` | 通常无需修改，继续使用整关卡 JSON 保存 |
| `server.js` | 通常无需修改，后端继续整体读写关卡数据 |
| `data/levels/*.json` | 可不手工修改，由归一化逻辑兼容旧格式 |
| `data/drafts/*.json` | 修改后自动保存新增墙体字段 |

## 10. 分阶段实施

### 阶段一：数据模型与渲染

- 墙体增加 `color` 和 `id` 字段。
- `normalizeLevel()` 补齐旧数据默认值。
- 渲染逻辑读取墙体颜色。
- 增加最小尺寸限制。

完成标准：旧关卡正常加载，新墙体可以保存并恢复颜色和尺寸。

### 阶段二：属性面板

- 增加墙体属性面板。
- 支持修改颜色、长度、厚度和位置。
- 输入后实时重绘。
- 修改结果写入草稿。

完成标准：选中墙体后可以通过面板完成全部基础属性修改。

### 阶段三：画布尺寸手柄

- 选中墙体绘制四角手柄。
- 支持拖拽手柄调整长度和厚度。
- 采用固定对角点计算。
- 增加最小尺寸限制。
- 拖拽结束后保存草稿。

完成标准：可以直接通过画布完成墙体尺寸调整，属性面板数值同步更新。

### 阶段四：命中与回归

- 选中、擦除和手柄命中统一使用墙体实际范围。
- 验证移动、缩放、删除操作互不冲突。
- 验证预览模式和碰撞逻辑。
- 验证导出、导入及旧数据兼容。

## 11. 风险与处理

| 风险 | 处理方案 |
|---|---|
| 旧墙体没有 `color` | 加载时由 `normalizeLevel()` 补默认颜色 |
| 输入尺寸为非法值 | 忽略非数字值，并限制最小尺寸 |
| 拖动手柄被识别为移动 | 手柄命中判断优先于墙体主体判断 |
| 墙体变大后擦除命中不准 | 使用基于墙体实际范围的 AABB 判断 |
| 拖拽过程中频繁保存造成性能问题 | 拖拽期间只重绘，`pointerUp` 时保存 |
| 属性面板和场景数据不一致 | 不复制墙体对象，直接修改统一状态 |
| 手柄拖动跨越固定边 | 约束最小尺寸，第一版不支持反向翻转 |

第一版建议禁止拖拽手柄跨越固定边，避免出现负宽度、负高度和墙体翻转。后续如有需求，可增加反向缩放支持。

## 12. 验收标准

1. 新建墙体后拥有默认颜色、长度和厚度。
2. 选中墙体后显示属性面板。
3. 修改颜色后画布实时更新。
4. 修改长度和厚度后墙体尺寸实时更新。
5. 修改 X/Y 坐标后墙体位置实时更新。
6. 拖动四个角手柄可以调整墙体尺寸。
7. 拖动手柄时固定对角点位置不变。
8. 墙体尺寸不会小于最小值。
9. 属性面板数值与画布调整结果保持同步。
10. 修改结果保存到 `data/drafts/*.json`。
11. 重新加载草稿后墙体属性不丢失。
12. 加载旧版墙体数据时可以自动补默认颜色。
13. 墙体尺寸变化后碰撞范围同步变化。
14. 墙体变大或变小后橡皮擦按实际范围命中。
15. 导出、导入 JSON 后颜色、尺寸和位置保持一致。
16. 游戏预览、模板应用和关卡保存功能无回归问题。

## 13. 暂不实现范围

第一版暂不实现：

- 墙体旋转。
- 非矩形墙体。
- 圆角和复杂材质。
- 渐变色、纹理和透明度。
- 多墙体批量编辑。
- 多选后的统一缩放。
- 墙体尺寸反向翻转。
- 撤销和重做历史记录。

以上能力待基础墙体属性编辑稳定后，根据实际编辑效率需求扩展。
