# 玩家本体与关卡预览界面问题修复方案

## 1. 问题概述

当前发现以下问题：

1. 玩家本体最外层武器圆环上的白色小球没有自动旋转。
2. 点击或长按射击无明显反应；即使生成子弹，子弹也从玩家中心点发射，而不是从武器小球位置发射。
3. 关卡预览界面中玩家无法使用 `WASD` 移动。
4. 关卡预览界面右侧仍显示实体属性编辑面板，属性面板应只在编辑界面出现。

问题主要集中在：

- `src/game-scene.js`：玩家动画、输入、射击和子弹生成。
- `src/main.js`：模式切换和属性面板同步。
- `index.html`：属性面板 DOM 结构。
- `src/style.css`：预览界面布局。

## 2. 当前实现定位

### 2.1 最外层白色小球没有自动旋转

当前 `drawHexRingPlayer()` 中，武器小球角度直接取玩家中心到鼠标指针的方向：

```js
const weaponAngle = Phaser.Math.Angle.Between(
  centerX,
  centerY,
  pointer.x,
  pointer.y
);
```

因此小球只会指向鼠标，不会随时间自动旋转。

正确做法：

- 角度存储在玩家运行时状态 `player.weaponAngle` 中。
- 白色小球自动绕玩家本体中心旋转，不跟随鼠标指针定位。
- 在 `update()` 中按 `delta` 累加角度。
- `draw()` 只读取 `player.weaponAngle`，不重新根据鼠标计算小球角度。
- 鼠标指针不参与玩家武器小球位置和子弹方向计算。

### 2.2 射击无反应及发射位置错误

当前射击判断使用：

```js
if (pointer.isDown && this.fireClock <= 0) {
  const angle = Phaser.Math.Angle.Between(
    this.player.x,
    this.player.y,
    pointer.x,
    pointer.y
  );

  this.bullets.push({
    x: this.player.x,
    y: this.player.y,
    vx: Math.cos(angle) * 500,
    vy: Math.sin(angle) * 500
  });
}
```

存在两个问题：

- `pointer.isDown` 未明确区分左键和右键，可能导致输入判断不稳定。
- 子弹初始坐标直接使用 `this.player.x/y`，所以子弹从玩家中心点发射。

应改为：

- 使用左键专用状态。
- 根据武器小球当前角度计算炮口位置。
- 子弹初始位置使用炮口坐标。
- 射击方向使用玩家中心到武器小球的连线方向，不使用鼠标指针方向。

### 2.3 预览界面无法使用 `WASD`

当前场景虽然注册了键盘输入：

```js
this.keys = this.input.keyboard.addKeys('W,A,S,D,UP,DOWN,LEFT,RIGHT');
```

但需要确认 Phaser Canvas 是否获得键盘焦点，以及预览模式是否正确启动了游戏场景。

常见原因：

- 切换到预览模式后 Canvas 没有焦点。
- 键盘事件被页面或输入控件拦截。
- `setMode('play')` 销毁并重新创建场景后，键盘插件尚未重新绑定。
- 预览时仍处于编辑模式状态，`update()` 提前执行 `if (this.editing) return`。

修复时需要保证：

```text
进入预览模式
  ↓
销毁旧场景
  ↓
创建新 Phaser 场景
  ↓
设置 Canvas / Phaser 键盘输入可用
  ↓
WASD 驱动玩家移动
```

### 2.4 预览界面显示属性面板

`index.html` 中属性面板位于游戏舞台区域：

```html
<section id="entity-properties" class="entity-properties" hidden>
  ...
</section>
```

`src/main.js` 的 `renderEntityProperties()` 只根据 `state.selected` 控制显示，没有根据当前模式限制：

```js
dom.entityProperties.hidden = !entity;
```

进入游戏预览后，如果编辑模式残留了选中实体，属性面板仍可能被渲染出来。

正确规则：

```text
编辑模式 + 选中实体 → 显示
编辑模式 + 未选中实体 → 隐藏
预览模式 → 始终隐藏
```

## 3. 当前代码核查结论与明确需求

经核查当前 `src/game-scene.js`，玩家武器小球的旋转和射击逻辑尚未达到设计要求。

### 3.1 当前代码问题

当前 `drawHexRingPlayer()` 使用鼠标方向计算小球角度：

```js
const weaponAngle = Phaser.Math.Angle.Between(
  centerX,
  centerY,
  pointer.x,
  pointer.y
);
```

因此当前表现是小球跟随鼠标指针，不是自动绕玩家本体旋转。

当前射击逻辑使用：

```js
if (pointer.isDown && this.fireClock <= 0) {
  const angle = Phaser.Math.Angle.Between(
    this.player.x,
    this.player.y,
    pointer.x,
    pointer.y
  );

  this.bullets.push({
    x: this.player.x,
    y: this.player.y,
    vx: Math.cos(angle) * 500,
    vy: Math.sin(angle) * 500
  });
}
```

存在以下缺口：

- 未区分鼠标左键和右键。
- 没有小球自动旋转角度状态。
- 没有默认顺时针旋转逻辑。
- 没有射击期间降速逻辑。
- 没有松开左键后的反向旋转逻辑。
- 子弹从玩家中心点生成。
- 子弹方向使用鼠标指针方向，不符合径向射击要求。

### 3.2 必须满足的旋转需求

| 状态 | 小球行为 | 角速度 |
|---|---|---:|
| 默认空闲 | 绕玩家本体中心顺时针旋转 | 180°/秒 |
| 按住左键射击 | 继续沿当前方向绕玩家中心旋转 | 20°/秒 |
| 松开左键 | 旋转方向反向 | 后续按当前状态速度执行 |

“每次射击后”定义为一次完整的左键按下并松开过程。反向动作只在左键状态从按下变为松开时触发一次，不应在持续按住左键期间重复触发。

### 3.3 必须满足的射击需求

```text
小球位置：由 weaponAngle 计算
子弹发射点：武器小球位置
子弹发射方向：玩家中心 → 武器小球的连线方向
鼠标指针：不参与射击方向计算
```

小球位于玩家武器圆环中心线上时，子弹沿该中心线向外发射：

```js
const muzzle = getWeaponOrbPosition(player);
const angle = player.weaponAngle;

bullet.x = muzzle.x;
bullet.y = muzzle.y;
bullet.vx = Math.cos(angle) * bulletSpeed;
bullet.vy = Math.sin(angle) * bulletSpeed;
```

### 3.4 必须增加的运行时状态

```js
this.player = {
  ...l.spawn,
  weaponAngle: 0,
  weaponDirection: 1,
  previousFireDown: false,
  firing: false
};
```

字段说明：

| 字段 | 说明 |
|---|---|
| `weaponAngle` | 小球绕玩家中心的当前角度 |
| `weaponDirection` | 旋转方向，`1` 表示默认顺时针，`-1` 表示反向 |
| `previousFireDown` | 上一帧左键是否按下 |
| `firing` | 当前是否处于左键长按射击状态 |

这些字段属于玩家运行时状态，不写入关卡 JSON。

## 4. 总体修复方案

### 3.1 玩家运行时状态增加武器动画状态

在 `restart()` 初始化玩家时增加：

```js
this.player = {
  ...l.spawn,
  r: 13,
  scheme: l.spawn.scheme || 'default',
  weapon: {
    ringColor: '#ff9f43'
  },
  weaponAngle: 0,
  weaponDirection: 1,
  previousFireDown: false,
  firing: false
};
```

字段说明：

| 字段 | 说明 |
|---|---|
| `weaponAngle` | 最外层武器小球当前角度 |
| `weaponDirection` | 旋转方向，`1` 或 `-1` |
| `previousFireDown` | 上一帧左键状态 |
| `firing` | 当前是否长按左键射击 |
| `weapon` | 当前武器配置 |

不要把动画角度写入关卡 JSON。该字段属于运行时状态。

## 4. 修复最外层小球自动旋转

### 4.1 角度更新

在游戏模式 `update(_, dt)` 中增加武器动画更新：

```js
const pointer = this.input.activePointer;
const fireDown = pointer.leftButtonDown();

if (this.player.previousFireDown && !fireDown) {
  this.player.weaponDirection *= -1;
}

const angularSpeed = fireDown
  ? Phaser.Math.DegToRad(20)
  : Phaser.Math.DegToRad(180);

this.player.weaponAngle +=
  this.player.weaponDirection * angularSpeed * dt / 1000;

this.player.weaponAngle = Phaser.Math.Angle.Wrap(
  this.player.weaponAngle
);

this.player.firing = fireDown;
this.player.previousFireDown = fireDown;
```

规则：

| 状态 | 角速度 |
|---|---:|
| 空闲 | 180°/秒 |
| 左键长按射击 | 20°/秒 |
| 左键松开 | 旋转方向反向 |

### 4.2 绘制读取运行时角度

将当前：

```js
const weaponAngle = Phaser.Math.Angle.Between(
  centerX,
  centerY,
  pointer.x,
  pointer.y
);
```

替换为：

```js
const weaponAngle = player.weaponAngle || 0;
```

`drawHexRingPlayer()` 不再依赖鼠标指针参数：

```js
function drawHexRingPlayer(graphics, player) {
  const centerX = player.x;
  const centerY = player.y;
  const weaponColor = player.weapon?.ringColor || '#ff9f43';
  const weaponAngle = player.weaponAngle || 0;

  drawHexagonBody(graphics, centerX, centerY);
  drawRing(graphics, centerX, centerY, PLAYER_ART.innerRingRadius, PLAYER_ART.innerRingThickness, weaponColor);
  drawRing(graphics, centerX, centerY, PLAYER_ART.outerRingRadius, PLAYER_ART.outerRingThickness, weaponColor);
  drawRing(graphics, centerX, centerY, PLAYER_ART.bodyRingRadius, PLAYER_ART.bodyRingThickness, '#ffffff');
  drawRing(graphics, centerX, centerY, PLAYER_ART.weaponRingRadius, PLAYER_ART.weaponRingThickness, weaponColor);

  const orb = getWeaponOrbPosition(player);
  graphics.fillStyle(0xffffff);
  graphics.fillCircle(orb.x, orb.y, PLAYER_ART.weaponOrbRadius);
}
```

### 4.3 Phaser 坐标系说明

Canvas 的 Y 轴向下，角度增加时视觉方向为顺时针。为保证表现稳定，不应再使用鼠标方向覆盖动画角度。

如实际运行发现方向与需求相反，只需将：

```js
player.weaponDirection = 1;
```

改为：

```js
player.weaponDirection = -1;
```

不要同时修改角度计算和绘制坐标，避免方向逻辑分散。

## 5. 修复射击逻辑

### 5.1 左键专用判断

使用 Phaser Pointer 的左键判断：

```js
const fireDown = pointer.leftButtonDown();
```

不要使用：

```js
pointer.isDown
```

因为 `isDown` 可能同时响应右键，导致护盾、射击和普通鼠标输入相互干扰。

### 5.2 计算武器小球位置

增加统一函数：

```js
function getWeaponOrbPosition(player) {
  return {
    x: player.x + Math.cos(player.weaponAngle || 0) * PLAYER_ART.weaponRingRadius,
    y: player.y + Math.sin(player.weaponAngle || 0) * PLAYER_ART.weaponRingRadius
  };
}
```

绘制和射击必须共用该函数，避免视觉小球位置与子弹发射位置不一致。

### 5.3 从武器小球发射子弹

修改射击逻辑：

```js
if (fireDown && this.fireClock <= 0) {
  const muzzle = getWeaponOrbPosition(this.player);
  const angle = this.player.weaponAngle || 0;

  this.bullets.push({
    x: muzzle.x,
    y: muzzle.y,
    vx: Math.cos(angle) * 500,
    vy: Math.sin(angle) * 500,
    trailColor: this.player.weapon?.ringColor || '#ff9f43'
  });

  this.fireClock = 180;
}
```

结果：

```text
玩家中心
  ↓
武器圆环中心线
  ↓
白色武器小球
  ↓
子弹从小球位置生成
```

### 5.4 射击方向规则

本次修复采用以下规则：

```text
小球运动：自动绕玩家中心旋转
发射点：武器小球位置
发射方向：玩家中心 → 武器小球的径向方向
鼠标指针：不参与射击方向计算
```

角度直接复用 `player.weaponAngle`：

```js
const angle = player.weaponAngle || 0;
const direction = {
  x: Math.cos(angle),
  y: Math.sin(angle)
};
```

这样可以保证：

- 子弹从白色小球位置生成。
- 子弹沿玩家中心到小球的连线向外发射。
- 小球旋转到哪里，子弹就从哪里沿径向射出。
- 鼠标移动不会改变当前射击方向。

如果后续需要鼠标瞄准，应另行设计瞄准模式，不与本次径向射击规则混用。

### 5.5 射击反馈

为确认射击逻辑生效，建议增加最小反馈：

- 子弹起点出现一个白色或橙色短闪点。
- 子弹主体使用武器颜色。
- 子弹保留短拖尾。

反馈仍使用 Graphics 绘制，不新增 Sprite 资源。

## 6. 修复预览界面 WASD 移动

### 6.1 初始化键盘

在 `create()` 中保留键盘初始化，并增加焦点处理：

```js
this.keys = this.input.keyboard.addKeys({
  W: Phaser.Input.Keyboard.KeyCodes.W,
  A: Phaser.Input.Keyboard.KeyCodes.A,
  S: Phaser.Input.Keyboard.KeyCodes.S,
  D: Phaser.Input.Keyboard.KeyCodes.D,
  UP: Phaser.Input.Keyboard.KeyCodes.UP,
  DOWN: Phaser.Input.Keyboard.KeyCodes.DOWN,
  LEFT: Phaser.Input.Keyboard.KeyCodes.LEFT,
  RIGHT: Phaser.Input.Keyboard.KeyCodes.RIGHT
});
```

进入游戏场景后启用键盘输入：

```js
this.input.keyboard.enabled = true;
```

如果页面存在输入框焦点，应在进入预览时让 Canvas 获得焦点：

```js
this.game.canvas.setAttribute('tabindex', '0');
this.game.canvas.focus();
```

### 6.2 统一移动逻辑

在 `update()` 中只在游戏模式处理玩家移动：

```js
if (this.editing) {
  this.draw();
  return;
}

if (this.state !== 'playing') return;

let dx = 0;
let dy = 0;

if (this.keys.A.isDown || this.keys.LEFT.isDown) dx -= 1;
if (this.keys.D.isDown || this.keys.RIGHT.isDown) dx += 1;
if (this.keys.W.isDown || this.keys.UP.isDown) dy -= 1;
if (this.keys.S.isDown || this.keys.DOWN.isDown) dy += 1;

const length = Math.hypot(dx, dy);
if (length > 0) {
  const speed = 180;
  this.player.x = Phaser.Math.Clamp(
    this.player.x + dx / length * speed * dt / 1000,
    15,
    W - 15
  );
  this.player.y = Phaser.Math.Clamp(
    this.player.y + dy / length * speed * dt / 1000,
    15,
    H - 15
  );
}
```

### 6.3 模式切换要求

`setMode('play')` 需要保证：

1. `state.mode` 先切换为 `play`。
2. `editorPanel` 隐藏。
3. 销毁旧 Phaser Game。
4. 重新创建游戏场景。
5. 新场景读取 `state.mode !== 'editor'`，设置 `this.editing = false`。
6. 场景创建后 Canvas 获取焦点。

现有 `constructor()` 使用：

```js
this.editing = ctx.state.mode === 'editor';
```

该逻辑可以保留，但必须保证新场景创建前状态已经切换。

### 6.4 防止页面快捷键干扰

如果浏览器或页面控件拦截 `WASD`，可在游戏预览期间监听键盘事件并阻止默认行为：

```js
const movementKeys = new Set(['w', 'a', 's', 'd']);

window.addEventListener('keydown', event => {
  if (state.mode !== 'editor' && movementKeys.has(event.key.toLowerCase())) {
    event.preventDefault();
  }
});
```

优先使用 Phaser Keyboard Plugin；只有确认页面焦点或默认行为造成干扰时，再增加该兜底逻辑。

### 6.5 屏蔽浏览器右键功能

右键用于激活护盾，必须阻止 Canvas 上的浏览器默认右键菜单、右键手势和相关弹窗。建议在 Phaser 场景 `create()` 中绑定：

```js
this.game.canvas.addEventListener('contextmenu', event => {
  event.preventDefault();
});
```

为覆盖部分浏览器的右键手势和按键默认行为，可同时监听 Canvas 的右键按下事件：

```js
this.game.canvas.addEventListener('mousedown', event => {
  if (event.button === 2) {
    event.preventDefault();
  }
});
```

如果浏览器仍然触发右键手势，可在 Canvas 上增加 CSS：

```css
#game canvas {
  user-select: none;
  -webkit-user-select: none;
  -webkit-touch-callout: none;
}
```

处理范围只限制在游戏 Canvas，不影响编辑器侧栏、输入框和页面其他区域的正常右键功能。事件监听应在场景销毁时移除，避免重复创建场景后重复绑定：

```js
create() {
  this.blockContextMenu = event => event.preventDefault();
  this.game.canvas.addEventListener('contextmenu', this.blockContextMenu);
}

shutdown() {
  this.game.canvas.removeEventListener('contextmenu', this.blockContextMenu);
}
```

如果项目需要整个游戏预览页面都禁用右键，而不只是 Canvas，则将监听目标改为 `dom.game` 或页面容器，并在进入编辑模式时解除监听。推荐优先限制在 Canvas 范围，降低对编辑器操作的影响。

## 7. 隐藏预览模式属性面板

### 7.1 同步逻辑增加模式判断

修改 `renderEntityProperties()`：

```js
function renderEntityProperties() {
  const entity = state.selected;

  if (state.mode !== 'editor') {
    dom.entityProperties.hidden = true;
    dom.entityFields.replaceChildren();
    return;
  }

  const l = state.level;
  const type = entity === l.spawn
    ? '玩家出生点'
    : l.walls.includes(entity)
      ? '墙体'
      : l.enemies.includes(entity)
        ? '敌人'
        : l.triggers.includes(entity)
          ? '触发器'
          : '';

  dom.entityProperties.hidden = !entity;
  dom.entityTitle.textContent = type ? `${type}属性` : '实体属性';
  if (!entity) return;

  // 原有编辑字段生成逻辑
}
```

关键要求：模式不是编辑器时，函数第一时间隐藏面板并清空字段。

### 7.2 模式切换时主动隐藏

在 `setMode()` 中增加：

```js
function setMode(mode) {
  state.mode = mode;
  document.body.classList.toggle('play-mode', mode !== 'editor');
  dom.editorPanel.hidden = mode !== 'editor';
  dom.editorPanel.style.display = mode === 'editor' ? '' : 'none';

  if (mode !== 'editor') {
    dom.entityProperties.hidden = true;
    dom.entityFields.replaceChildren();
  }

  if (state.game) {
    state.game.destroy(true);
    state.game = null;
  }

  startGame();
  sync();
}
```

切回编辑模式时再通过 `sync()` 根据当前选中对象决定是否显示属性面板。

### 7.3 清理编辑器选中状态的可选方案

预览开始时可以清空编辑器选中对象：

```js
if (mode !== 'editor') {
  state.selected = null;
}
```

是否清空取决于是否需要返回编辑模式后保留选中对象。推荐不依赖清空状态解决问题，仍以 `state.mode` 作为属性面板显示条件；这样切回编辑模式时可以保留原选中对象。

## 8. 代码拆分建议

当前 `src/game-scene.js` 的 `update()` 和 `draw()` 逻辑较长，建议本次修复至少抽出以下函数：

```js
function getWeaponOrbPosition(player) {}
function updateWeaponAnimation(player, pointer, dt) {}
function spawnPlayerBullet(scene, pointer) {}
function updatePlayerMovement(scene, dt) {}
function isFireDown(pointer) {}
```

场景内部调用：

```js
update(_, dt) {
  if (this.editing) return this.draw();
  if (this.state !== 'playing') return;

  updatePlayerMovement(this, dt);
  updateWeaponAnimation(this.player, this.input.activePointer, dt);
  this.updateShooting(dt);
  this.updateBullets(dt);
  this.updateEnemies(dt);
  this.draw();
}
```

这样可以避免后续加入护盾、蓝图和武器类型时继续扩大单行函数。

## 13. 风险与注意事项

### 13.1 Canvas 坐标和角速度方向

Phaser 使用屏幕坐标，Y 轴向下。角度正方向的视觉效果需要通过实际运行确认。如果旋转方向反了，只调整 `weaponDirection` 初始值，不修改射击和绘制坐标逻辑。

### 13.2 左右键输入冲突

不能继续使用泛化的 `pointer.isDown` 同时处理射击和护盾。必须分别使用左键和右键状态，否则右键可能触发射击，左键状态也可能影响护盾。

### 13.3 编辑模式场景输入

编辑模式仍需要鼠标点击、拖拽和实体选择。因此不能全局关闭 Phaser 输入，只能在游戏模式下启用对应的玩家控制分支。

### 13.4 属性面板显示时机

CSS 隐藏只能作为兜底，主要逻辑必须由 `renderEntityProperties()` 和 `setMode()` 控制。否则切换模式时可能出现 DOM 状态与应用状态不一致。

## 14. 最终建议

本次修复不建议直接重写整个场景。推荐先完成四个最小改动：

```text
运行时 weaponAngle
  ↓
统一 getWeaponOrbPosition()
  ↓
左键专用射击 + 从小球发射
  ↓
预览模式键盘焦点与 WASD
  ↓
属性面板按 mode 隔离
```

修复完成后，再将玩家本体逻辑迁移到前一版规划的 `player-default` 蓝图，避免本次 Bug 修复与蓝图系统重构同时进行，降低回归风险。
